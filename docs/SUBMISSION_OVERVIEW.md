# Submission overview

Source: https://github.com/Jayadityas/DevDesk_AI_Employee. Setup/run instructions are in README and SETUP_AND_DEMO. Demo video: [Watch DevDesk on Loom](https://www.loom.com/share/398ea7183b0b483f863caeb1ef3ba4fb).

Architecture: authenticated DevDesk C++ control plane stores workflow in PostgreSQL; a separate C++/SQLite Team Tasks app supplies controlled repair targets; a bounded model worker uses fixed tools and a protected Docker evaluator. Source changes happen in task worktrees. Scope approval precedes edits; exact candidate acceptance precedes local integration; integrated PASS evidence gates COMPLETED. Features also require a fixed-roster two-thirds vote.

Important decisions: C++ matches the builder's preferred language and enables explicit RAII resource ownership. SQLite keeps synthetic app data simple, while PostgreSQL supports durable transactional workflow and queue locks. Fixed typed model tools are validated outside model-edited source. Independent checks and source identity replace trust in model claims. Container restrictions and a separate backend evaluator UID protect tested result/process boundaries. Scope permission and candidate acceptance are separate to prevent broad or stale consent. Snapshot voting prevents denominator changes from silently lowering a feature threshold. Local Git kept the prototype bounded while retaining a future PR/admin design.

Assumptions: synthetic local employees/data; one Windows host/project capacity; controlled localhost playground URLs; working Linux Docker engine; installed compiler/PostgreSQL/Node/Chrome dependencies; a locally configured Gemini key; a reporter available for scope and candidate decisions. Model output and reports/screenshots/source content are untrusted. Existing services/data must be preserved. Tests with simulated human decisions are labeled separately from actual model inference.

Demonstrated outcomes: mobile layout20 candidate/integrated assertions; backend filter26; Completed feature22. All passed in recorded successful runs. Earlier failures and differing releases are retained, so these are not a model reliability percentage. The recording Workbench is a presentation copy of those actual completions; recorded evidence is not replayed inference.

Known limitations: three registered repair/feature capabilities, foreground workers, local Git integration, Windows installation paths, synthetic account model, no arbitrary application migrations or distributed exactly-once guarantee. Docker had intermittent HTTP500 failures. Specific isolation/recovery boundaries were tested, not every exploit or crash point. A separate-machine dependency/cluster installation was not demonstrated. The detailed disclosure names these limits and AI assistance.

With more time: connect GitHub contributor PRs, linked reporter reviews and separate merge-admin notifications; observe actual merged-main before completing requests; add background service supervision, broader independently evaluated capabilities, stronger operational monitoring and cross-machine setup verification.

Models/APIs/components: user-selected Gemini gemini-3.5-flash-lite alias over Google generateContent/WinHTTP, strict response schemas; an alternative OpenAI adapter exists but final live runs used Gemini. C++20/GCC, cpp-httplib0.60.1, nlohmann/json3.12.0, SQLite, PostgreSQL17.11, plain HTML/CSS/JS, Node24, Playwright1.64.0, Chrome/Chromium, Docker Linux and local Git. Codex assisted code/tests/docs.
